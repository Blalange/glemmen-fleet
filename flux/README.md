# Flux

GitOps for the Talos cluster, replacing Fleet. Flux is bootstrapped into
`flux/clusters/glemmen/` and syncs everything from this repository.

## Layout

```
flux/
├── setup.sh                    bootstrap Flux (GITHUB_TOKEN + KUBECONFIG)
├── manage.sh                   status / sync / suspend / resume helpers
├── clusters/glemmen/           entry points, synced by the root Kustomization
│   ├── flux-system/            (generated by `flux bootstrap`)
│   ├── infrastructure.yaml     -> flux/infrastructure
│   ├── cert-manager-issuers.yaml    -> cert-manager/issuers (chart -> issuers)
│   ├── cert-manager-certificates.yaml -> cert-manager/certificates (-> kube-system)
│   ├── ingress.yaml            -> flux/ingress (Traefik, depends on certificates)
│   ├── monitoring-pvc.yaml     -> kube-prometheus-stack/pvc (Grafana volume + SC)
│   ├── monitoring.yaml         -> flux/monitoring (KPS, smartctl, unpoller)
│   ├── monitoring-dashboards.yaml / monitoring-alerts.yaml
│   └── apps.yaml               -> flux/apps (application Kustomizations)
├── infrastructure/             namespaces, Longhorn, cert-manager, MetalLB, metrics-server
├── ingress/                    Traefik HelmRelease + values
├── monitoring/                 kube-prometheus-stack, smartctl-exporter, unpoller
└── apps/                       Kustomization objects + Homepage HelmRelease
```

The application manifests themselves stay in the repository root (`colibri/`,
`energisjappa/`, `frigate/`, `homepage/`, `panel/`, `snipe-it/`, `unifi/`,
`cert-manager/`, `kube-prometheus-stack/`) — the Flux Kustomizations point at
those directories. The old `fleet.yaml` files and the values files that moved
into `flux/` have been deleted.

Helm values live next to their HelmRelease and are turned into ConfigMaps with
`configMapGenerator`; the HelmRelease reads them through `valuesFrom`.

## Daily use

```sh
./flux/manage.sh status                  # everything at a glance
./flux/manage.sh sync                    # pull the latest Git revision now
./flux/manage.sh reconcile homepage      # re-apply one Kustomization
./flux/manage.sh apps-off                # suspend application workloads
./flux/manage.sh apps-on                 # resume them
./flux/manage.sh freeze / unfreeze       # suspend/resume everything
```

`flux reconcile` / `flux get` / `flux logs` also work directly if you prefer.

## Dependencies (was Fleet `dependsOn`)

- `infrastructure` (namespaces, Longhorn, cert-manager chart, MetalLB, metrics-server)
- `cert-manager-issuers` -> `cert-manager-certificates` -> `ingress` (Traefik)
- `infrastructure` -> `monitoring-pvc` -> `monitoring` -> `monitoring-dashboards` / `monitoring-alerts`
- `apps` waits for `infrastructure`, `monitoring` and `ingress`; the individual
  applications additionally wait for what they need (`homepage` for example
  waits for `homepage-assets`, `kube-prometheus-stack` and `infrastructure`).

## Migration notes

- **Secrets are not in Git.** Before the apps become healthy, restore the
  secret dumps taken in the backup step (`scripts/restore-to-new-cluster.sh`):
  Cloudflare tokens (cert-manager), `grafana-admin`, `unpoller-unifi`,
  `homepage-grafana`, `frigate-secrets`, `energisjappa-secrets`, `colibri-secrets`,
  `snipe-it-db`, `snipe-it-app-key` and the TLS certificates in `kube-system`.
- **Longhorn volumes are restored from the NFS backupstore** on glemmen60
  (`scripts/restore-to-new-cluster.sh`), before the application Kustomizations
  are resumed.
- **Load balancer cutover.** Traefik currently advertises `192.168.6.97`
  (`flux/ingress/traefik/values.yaml`). At cutover:
  1. stop and disable keepalived on the old nodes (`glemmen170/180/80`),
  2. change `metallb.io/loadBalancerIPs` to `192.168.6.99`,
  3. `./flux/manage.sh sync` (or `flux reconcile kustomization ingress --with-source`),
  4. verify `https://glem.men` and the other hosts, then raise the TTL/keep the
     old cluster powered off but intact until the new cluster is proven.
  The UniFi port forwards (80/443 -> 192.168.6.99) stay untouched. Future
  services can share `.99` on other ports with MetalLB (`autoAssign` is off, so
  they must ask for the IP explicitly, see `metallb/pool.yaml`).
- **Disable Fleet before pushing this refactor.** The old cluster is still
  managed by Fleet until its GitRepo is paused/deleted in Rancher; the commit
  that deletes `fleet.yaml` must not be synced back to the old cluster, or the
  Fleet bundles will fail to render (running workloads keep running, but the
  bundles go NotReady).
- **Permanent backup target.** The migration uses the NFS export on glemmen60.
  Once the new cluster is established, switch Longhorn's
  `defaultBackupStore.backupTarget` to the in-cluster SeaweedFS S3 store
  (repo intent, `longhorn-weed-credentials` secret) — see the migration plan,
  step 8.
